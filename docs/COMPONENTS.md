# การแยกเป็นคอมโพเนนต์ — สถานะและแผน

## สถานะจริง ณ ตอนนี้

**ยังไม่ใช่ component-driven** และไม่ควรเรียกแบบนั้น

`src/modules/` ดูเหมือนโมดูล แต่เป็น **ชิ้นข้อความที่ถูกฉีดเข้าไปใน global scope เดียวกัน**
ของ `src/base.html` ไม่มี import/export ไม่มีขอบเขต ทดสอบเดี่ยว ๆ ไม่ได้

วัดด้วย `node tools/deps.js` — นับว่าแต่ละไฟล์ **ใช้ชื่อจากข้างนอกกี่ตัว**:

```
module            lines  defines  outside names it needs
──────────────────────────────────────────────────────────
hatch.js             52        8   6
recover.js          341       15  13
idb.js               83       13  16
migrate.js          135       29  16
section.js          303       38  18
stylize.js           70       15  19
dimmodel.js         613      134  26
dxfexport.js        413       62  33
balloon.js          181       54  36
dimgrips.js         284       49  38
```

ยิ่งตัวเลขขวาสูง ยิ่งแยกออกมายาก `dimgrips`/`balloon` แตะ `ctx`, `view`, `selIds`,
`store` โดยตรง — เป็น UI layer ที่ต้องแยกทีหลังสุด

## สองชั้นที่ควรเป็น

```
src/lib/      คอมโพเนนต์จริง — รับตัวเลข คืนตัวเลข ไม่แตะ DOM ไม่แตะ global
              ทดสอบใน Node เป็นมิลลิวินาที · ใช้ซ้ำที่ไหนก็ได้

src/modules/  ชั้นที่ต้องมี canvas/DOM — วาด, ลาก, เลือก, เก็บข้อมูล
              ทดสอบด้วยเบราว์เซอร์จริงเท่านั้น
```

`scripts/build.py` เอา `src/lib/*.mjs` มาแทรกโดยตัดคำว่า `export` ออก
เพราะแอปยังเป็น global scope เดียว — เมื่อ `base.html` ถูกแยกเสร็จ ขั้นตอนนี้จะหายไป
และ import จะกลายเป็นของจริง

## ทำไปแล้ว 1 ตัว — และมันคุ้มทันที

`src/lib/hatch-pattern.mjs` (11 unit test, รันใน ~50 ms)

**ภายในไม่กี่นาทีหลังมีเทสต์ มันเจอบั๊กที่เทสต์เบราว์เซอร์ 63 ตัวมองไม่เห็น:**

DXF เขียน `0` แทน **จุด** ซึ่งเป็นสิ่งที่ต้องวาด แต่โค้ดนับว่า "มีหมึก" เฉพาะเมื่อ `v > 0`
ลายที่เป็นจุดสลับช่องว่างจึงถูกทิ้งทั้งลาย

เทสต์เบราว์เซอร์จับไม่ได้เพราะไฟล์ตัวอย่างที่มีไม่มีลายแบบนั้น — แต่ unit test
ถามคำถามที่ไฟล์ตัวอย่างไม่ต้องมีอยู่ก็ตอบได้

## ลำดับที่แนะนำให้ทำต่อ

ทำทีละตัว รัน `bash scripts/test.sh` ทุกครั้ง **ถ้าตัวไหนทำให้พัง ให้ย้อนตัวนั้น
ไม่ใช่เดินหน้าต่อ**

| ลำดับ | ดึงอะไรออกมา | ทำไมง่าย | ได้อะไร |
|---|---|---|---|
| 1 | ~~hatch-pattern~~ | ✅ ทำแล้ว | 11 unit test · เจอบั๊ก 1 ตัว |
| 2 | **dxf-format** — `dxfNum`, `dxfStr`, `dxfLayerName`, `dxfLineType` | เป็นฟังก์ชันแปลงสตริงล้วน | ทดสอบ escape `%%c` และชื่อเลเยอร์ได้โดยไม่ต้องเปิดเบราว์เซอร์ |
| 3 | **geom** — `recFitCircle`, การหามุมกวาดของส่วนโค้ง, ตัดเส้นด้วยกฎ even-odd | คณิตล้วน ไม่แตะ DOM | เคสขอบที่ไฟล์ตัวอย่างไม่มี |
| 4 | **value-format** — `dimValueText`, `dimSplitValue`, `dimValueNumber` | รับสตริง คืนสตริง | ทศนิยม · คำนำหน้า `2x` · สัญลักษณ์ ⌀ |
| 5 | **dim-geometry** — `dimGeomOf` และเพื่อน ๆ | ต้องตัด `dimTextWidth` (ใช้ canvas วัด) ออกไปเป็น dependency ที่ส่งเข้ามา | ตัวใหญ่ที่สุด ได้ประโยชน์มากที่สุด |
| 6 | แยก `base.html`: CSS → `src/styles.css` แล้วโค้ดทีละก้อน | — | เลิกใช้ `build.py` ได้ในที่สุด |

**ข้อ 5 คือหัวใจ** `dimmodel.js` 613 บรรทัดเป็นตรรกะหลักทั้งหมด ติดอยู่กับข้างนอก
26 ชื่อ ซึ่งเกือบทั้งหมดเป็นค่าคงที่ (`PX_PER_MM`, `DIM_LW`) กับ `dimTextWidth`
ที่วัดข้อความด้วย canvas — ส่งเข้ามาเป็นพารามิเตอร์ได้

## กฎที่ควรยึดระหว่างแยก

**ไม่แยกเพื่อความสวย แยกเพื่อให้ทดสอบได้เร็วขึ้น**
ถ้าดึงออกมาแล้วยังต้องเปิดเบราว์เซอร์เพื่อทดสอบ แสดงว่ายังดึงไม่พอ

**ทุกคอมโพเนนต์ต้องมี unit test ก่อนถือว่าเสร็จ**
คอมโพเนนต์ที่ไม่มีเทสต์คือไฟล์ที่ย้ายที่ ไม่ได้ทำให้อะไรดีขึ้น

**เทสต์เบราว์เซอร์ต้องผ่านเท่าเดิมทุกขั้น**
การแยกโค้ดไม่ควรเปลี่ยนพฤติกรรม ถ้าเปลี่ยน แปลว่าแยกผิด

## วิธีรัน

```bash
bash scripts/unit.sh      # คอมโพเนนต์ — มิลลิวินาที
bash scripts/test.sh      # ทั้งระบบผ่านเบราว์เซอร์ — หลายนาที
node tools/deps.js        # ดูว่าตอนนี้แต่ละไฟล์ผูกกับข้างนอกแค่ไหน
```
