# หลักการทำงานของ STYLIZE

เอกสารนี้เขียนไว้เพื่อให้ STYLIZE **ทำงานกับไฟล์ใดก็ได้** ไม่ใช่เฉพาะไฟล์ตัวอย่าง
จึงเขียนเป็น **กฎ** (เจออะไร → ต้องเป็นอะไร) ที่วนกับทุกชิ้นในแบบ ไม่ใช่ขั้นตอน
ที่ปรับจูนกับรูปร่างของไฟล์ใดไฟล์หนึ่ง

---

## 0. หลักคิดพื้นฐาน 5 ข้อ

**ข้อ 0 — นำเข้าคือ "แสดงไฟล์" ไม่ใช่ "แก้ไฟล์"**

ตอน import ระบบ **อ่าน** ทุกอย่างเป็นโมเดล แต่ **ไม่วาดทับอะไรเลย** — แบบที่เห็น
คือแบบที่เจ้าของไฟล์วาดไว้ทุกเส้น การเปลี่ยนแปลงเกิดขึ้นตอนกด STYLIZE เท่านั้น

ถ้า import แก้ไปแล้วครึ่งหนึ่ง จะไม่มีทางบอกได้ว่าอะไรมาจากไฟล์และอะไรมาจากเรา
และไม่เหลืออะไรให้เทียบว่า STYLIZE ทำอะไรบ้าง

**วัดผล:** ภาพหลัง import ต่างจากตัวอ่านที่ไม่แก้อะไรเลย (บิลด์เก่า)
**1,079 พิกเซล** (Head-back) และ **1,976 พิกเซล** (Sheet3) — ส่วนต่างเป็นกรอบ
กับตารางชื่อแบบที่แอปวาดเอง ไม่ใช่เนื้อแบบ
พอกด STYLIZE ภาพเปลี่ยน **42,676** และ **35,372 พิกเซล**


**ข้อ 1 — อ่านจากสิ่งที่ไฟล์บอก ไม่ใช่จากรูปร่างที่วาดออกมา**

DXF บอกมาแล้วว่าอะไรคืออะไร (entity `DIMENSION` มีจุดที่วัด · มีชนิด · มีมุม)
การเดาจากเส้นที่วาด เช่น "เส้นที่ยาวที่สุดคือเส้นบอกระยะ" จะผิดทันทีที่เจอไฟล์ที่
เส้นฉายยาวกว่า ซึ่งเป็นเรื่องปกติ

**ข้อ 2 — เก็บเป็นโมเดล แล้ววาดจากโมเดล**

ทุกไดเมนชั่นและทุกเครื่องหมายหน้าตัดเป็น **object เดียวที่รู้ว่าตัวเองประกอบด้วยอะไร**
STYLIZE = **แก้ค่าในโมเดล** แล้ววาดใหม่ทั้งชุด ไม่ใช่ไปดัดเส้นที่วาดไว้แล้ว
ผลคือ **กดกี่ครั้งก็ได้ผลเดิม** เพราะเป็นการตั้งค่า ไม่ใช่การนวดสะสม

**ข้อ 3 — สิ่งที่วัดได้ต้องมาจากจุดที่วัด ไม่ใช่จากข้อความ**

ค่าที่แสดงคำนวณจาก `measure` เสมอ ยืดเส้นอย่างไรตัวเลขก็ไม่เปลี่ยน
และตอน export เขียน `<>` เพื่อให้โปรแกรมปลายทางวัดเอง ไม่ใช่ตรึงตัวเลขไว้

**ข้อ 4 — แตะเฉพาะงานอธิบายแบบ ห้ามแตะเนื้อแบบ**

เส้นชิ้นงาน · เส้นศูนย์กลางของชิ้นงาน · กรอบกระดาษ · ตารางชื่อแบบ
→ **ไม่แตะเลย** แม้แต่เส้นเดียว (มีเทสต์บังคับข้อนี้: `t_objdmg.js`)

## 1. ลูปหลัก

STYLIZE **ไม่ออกจากลูปตราบใดที่ยังหาของใหม่เจอ** และการกดอีกครั้งคือการ**สแกนใหม่ทั้งหมด**
ไม่ใช่เล่นซ้ำสิ่งที่ตัดสินไว้รอบก่อน

```
STYLIZE(หน้า):
  txtH ← ขนาดตัวอักษรจาก Format Config
  ทำซ้ำ (สูงสุด 6 รอบ):
    1. สแกนหาไดเมนชั่นที่ยังไม่มีโมเดล  → สร้างจากรูปทรง (§1b.4c)
       ถ้าเจอใหม่ → สร้าง object ใหม่แล้ววนต่อ
    2. วาดทุกโมเดลที่มี                → กฎหมวด A และ B
    3. ถ้ารอบนี้ไม่เจออะไรใหม่          → ออกจากลูป
  4. ข้อความที่ไม่ใช่ของใคร             → กฎหมวด C
  5. รายงานสิ่งที่ยังจับคู่ไม่ได้ พร้อมเหตุผล
```

ไม่มีที่ไหนในลูปนี้ที่อ้างถึงชื่อไฟล์ · ชื่อเลเยอร์เฉพาะ · หรือจำนวนชิ้น
เจอ 3 ตัวหรือ 300 ตัวก็เดินกฎเดียวกัน

**สิ่งที่ยังจับคู่ไม่ได้** = ตัวเลขที่มี**หัวลูกศรที่ยังไม่มีเจ้าของอยู่ใกล้ ๆ**
ไม่ใช่ตัวเลขทุกตัวบนแบบ — เลขโซนกรอบกระดาษ เลขหน้า และวันที่ ไม่ใช่ไดเมนชั่นที่ทำไม่สำเร็จ

## 1b. เจออะไรถึงนับว่าเป็น "อะไร" — เกณฑ์ระบุชนิด

ทุกกฎข้างล่างเริ่มจากคำถามเดียวกัน: **ชิ้นนี้คืออะไร** ถ้าตอบผิดตั้งแต่ตรงนี้
กฎที่ตามมาก็ผิดหมด เกณฑ์จึงต้องเป็นสิ่งที่ **ไฟล์ยืนยันได้** ไม่ใช่สิ่งที่ตาเห็น

### ลำดับการตัดสิน (ตัดสินได้แล้วหยุด ไม่ตกไปข้อถัดไป)

```
สำหรับทุก entity ที่นำเข้า:
  1. เป็น entity ที่ประกาศตัวเองไหม      → เชื่อมัน                    (§1b.1)
  2. อยู่บนเลเยอร์ที่ห้ามพิมพ์ไหม        → ข้าม                        (§1b.2)
  3. เข้าลายเซ็นเชิงรูปร่างของ section ไหม → เป็น section              (§1b.3)
  4. เป็นเครื่องเรือนของกระดาษไหม        → ห้ามแตะ                     (§1b.4)
  5. นอกนั้น                            → เนื้อแบบ หรือข้อความทั่วไป   (§1b.5)
```

### 1b.0 ถ้าไฟล์ไม่ประกาศอะไรเลย — สร้างขึ้นใหม่จากรูปร่าง

ไฟล์จำนวนมาก **ไม่มี entity `DIMENSION` เลย** เพราะถูกระเบิด (exploded)
ตอน export หรือมาจากโปรแกรมที่เขียนแต่เรขาคณิต

**วัดจริง:** เอาไฟล์ตัวอย่างทั้ง 3 มาระเบิดไดเมนชั่นทิ้ง แล้วนำเข้า → **อ่านได้ 0 ตัว**
STYLIZE จึงไม่มีอะไรให้แก้ นี่คือ "บางไฟล์แก้ไม่ได้" ที่เกิดขึ้นจริง

**หลักในการสร้างใหม่: ตัวเลขคือจุดยึด** — ตัวเลขบนแบบไม่ใช่ของประดับ มันคือ
ป้ายกำกับของการวัด และสิ่งที่ถูกวัดอยู่ข้าง ๆ มันเสมอ

| เจอ | สร้างเป็น | ต้องครบอะไรถึงจะยอมรับ |
|---|---|---|
| ตัวเลขมี `R` นำหน้า + หัวลูกศร 1 อันที่**ปลายแตะส่วนโค้งจริงในแบบ** (คลาด < 0.4 mm) | radius | ต้องมีวงกลม/ส่วนโค้งจริงรองรับ ไม่ใช่แค่ลูกศรลอย ๆ |
| ตัวเลขมี `⌀` / `%%c` + เงื่อนไขเดียวกัน | diameter | เหมือนกัน |
| ตัวเลขล้วน + **หัวลูกศร 2 อันหันหน้าเข้าหากันบนแนวเดียวกัน** (dot < −0.9, ขนานกับแนวที่เชื่อมปลาย > 0.98) และตัวเลขอยู่ชิดแนวนั้น (< 3.5 เท่าความสูงตัวอักษร) และอยู่ในช่วงระหว่างปลาย | linear | ครบทั้ง 3 เงื่อนไข |
| เส้นฉาย | หาเส้นตั้งฉากที่ยืนอยู่ที่ปลายลูกศร (คลาด < 0.8 mm) | ถ้าไม่เจอ ใช้ปลายลูกศรเป็นจุดวัดแทน |

**ระยะเว้นจากชิ้นงานตั้งเป็น 0** เพราะช่องว่างนั้นคือ *ที่ว่าง* — ไม่มีอะไรในไฟล์
บันทึกไว้ว่ากว้างเท่าไหร่ จุดที่วัดจึงเอาปลายเส้นฉายด้านที่ติดชิ้นงานตรง ๆ
เส้นที่วาดใหม่จึงอยู่ตรงที่เดิมเป๊ะ ไม่ใช่ตรงที่ระยะเว้นที่เดาเอาจะพาไป

**ยึดเฉพาะสิ่งที่เรียกชื่อได้** — หัวลูกศรที่จับคู่ได้ · เส้นฉายที่ตามไปเจอ ·
ตัวเลขที่อ่าน · และเส้นที่อยู่บนแนวเส้นบอกระยะของตัวเอง
(เวอร์ชันแรกของผมกวาดทุกอย่างใน "กรอบ" ของไดเมนชั่น แล้ว**กลืนเส้นชิ้นงานไป
ประมาณ 300 เส้นกับเครื่องหมายหน้าตัดทั้ง 2 อัน** — จับได้จากการวัดปริมาณเส้นทั้งหน้า)

**ลำดับสำคัญ:** ตรวจเครื่องหมายหน้าตัด**ก่อน** แล้วค่อยสร้างไดเมนชั่นใหม่
เพราะลายเซ็นของหน้าตัดชัดเจนกว่า และการจองไว้ก่อนกันไม่ให้ไดเมนชั่นไปแย่งหัวลูกศรของมัน

### 1b.1 สิ่งที่ประกาศตัวเอง — เชื่อไฟล์ ไม่ต้องเดา

| เจอ | นับเป็น | ตรวจจากอะไร |
|---|---|---|
| entity `DIMENSION` | ไดเมนชั่น | ชนิดของ entity ตรง ๆ |
| กลุ่ม 70 (3 บิตล่าง) = 0 | linear (หมุนได้ตามกลุ่ม 50) | ค่าในไฟล์ |
| = 1 | aligned | ค่าในไฟล์ |
| = 2 หรือ 5 | angular | ค่าในไฟล์ · **ยังไม่มีโมเดล → ปล่อยไว้** |
| = 3 | diameter | ค่าในไฟล์ |
| = 4 | radius | ค่าในไฟล์ |
| = 6 | ordinate | ค่าในไฟล์ · **ยังไม่มีโมเดล → ปล่อยไว้** |
| entity `HATCH` | ลายตัด | ชนิดของ entity ตรง ๆ |
| entity `ARC` / `CIRCLE` | ส่วนโค้ง / วงกลม | ชนิดของ entity — จำไว้เพื่อ export กลับเป็นของเดิม |

**ทุกชิ้นที่บล็อกของ `DIMENSION` วาดออกมา ถูกติดแท็กว่าเป็นของไดเมนชั่นตัวนั้น**
ตั้งแต่ตอน import จึงไม่ต้องหาทีหลังว่าเส้นไหนเป็นของใคร

**เงื่อนไขที่ต้องผ่านเพิ่มก่อนจะสร้างโมเดล** (ไม่ผ่าน = ปล่อยไว้ ไม่แตะ):

| ต้องมี | ทำไม |
|---|---|
| กลุ่ม 13 และ 14 ครบ (linear/aligned) | ไม่มีจุดที่วัด ก็ไม่รู้ว่าวัดอะไร |
| กลุ่ม 10 และ 15 ครบ (radius/diameter) | เช่นเดียวกัน |
| รัศมี > 0 | กันหารด้วยศูนย์ |
| เส้นที่บล็อกวาด **ไม่มีเส้นเฉียง**ที่ไม่ขนานและไม่ตั้งฉากกับแนวไดเมนชั่น | เส้นเฉียงแปลว่ามีเส้นชี้หรือรูปแบบพิเศษที่โมเดลยังไม่รู้จัก |
| โมเดลวาดทับของเดิมได้ **คลาด ≤ 0.35 mm** | ถ้าวาดแล้วไม่เหมือนเดิม แปลว่าอ่านผิด |

| เจอ | ทำอะไร |

### 1b.3 เครื่องหมายหน้าตัด — ระบุจากรูปร่าง ไม่ใช่ชื่อ

**ไม่ใช้ชื่อเลเยอร์เป็นตัวตัดสิน** เพราะแต่ละโปรแกรมตั้งชื่อไม่เหมือนกัน
และบางไฟล์วาดเส้นตัดบนเลเยอร์เส้นศูนย์กลาง

ลายเซ็นที่ต้องเข้าครบ **ทุกข้อ**:

| ต้องเจอ | เกณฑ์ | กันอะไร |
|---|---|---|
| หัวลูกศร 2 อัน **ชี้ไปทางเดียวกัน** | ทิศต่างกันไม่เกิน ~8° | ลูกศรไดเมนชั่นชี้เข้าหากัน จึงไม่เข้าเกณฑ์ |
| ปลายทั้งสองอยู่ห่างกันพอสมควร | > 15 mm | กันลูกศรคู่เล็ก ๆ ของไดเมนชั่นแคบ |
| แนวที่เชื่อมสองปลาย **ตั้งฉากกับทิศการมอง** | \|แนว · ทิศ\| < 0.08 | ระนาบตัดต้องขวางทิศที่มอง |
| มีตัวอักษรตัวเดียว (A–Z อาจมี `'`) **เป็นคู่** อยู่ใกล้ปลายทั้งสอง | ห่างจากปลาย < 30 mm | กันตัวอักษรโซนกรอบกระดาษ A–D/1–6 ที่ไม่มีลูกศรคู่ |

**เส้นที่จะยึดเป็นของ marker** (ลบได้) ต้องเข้าครบ:
อยู่ในแนวเดียวกับเส้นตัดหรือตั้งฉากกับมัน · อยู่ในกรอบของ marker (± 6 mm) ·
**และไฟล์ทำเครื่องหมายไว้ว่าเป็น section line**

เส้นที่อยู่ในแนวเดียวกันแต่ไม่ได้ถูกทำเครื่องหมาย → **อ่านได้เพื่อหาปลายเส้นตัด แต่ห้ามลบ**
(เพราะมักเป็นเส้นศูนย์กลางของชิ้นงาน — เคยลบไปแล้ว 14 เส้น)

### 1b.4 เครื่องเรือนของกระดาษ — ห้ามแตะ

เข้าข้อใดข้อหนึ่งก็นับ:

| เกณฑ์ | ทำไมต้องมีสองแบบ |
|---|---|
| ชื่อเลเยอร์เข้าข่าย `border` · `frame` · `title` | จับได้ส่วนใหญ่ |
| อยู่ใน**พื้นที่ตารางชื่อแบบ** ที่คำนวณจากกล่องครอบข้อความบนเลเยอร์ `title` ของไฟล์เอง (+ระยะเผื่อ 6 mm) | ตารางชื่อแบบมักเป็นบล็อก ซึ่ง attribute ข้างในใช้เลเยอร์อื่น — เจอจริง: `01` ในช่อง Edition อยู่บนเลเยอร์ `Symbol (ISO)` |
| อยู่ในกรอบ Title Block ของแอปเอง | สำหรับหน้าที่แอปสร้าง |

### 1b.4b ตรวจว่าเกณฑ์ "ปฏิเสธ" ได้จริง

เกณฑ์ที่รับอย่างเดียวไม่ใช่เกณฑ์ ต้องปฏิเสธของที่หน้าตาคล้ายได้ด้วย
ไฟล์ `classify_test.dxf` จึงใส่ตัวล่อไว้ 3 อย่างพร้อมของจริง 1 อย่าง:

| สิ่งที่ใส่ไว้ | ควรถูกนับเป็น | ผล |
|---|---|---|
| หัวลูกศร 2 อันชี้ทางเดียวกัน + ตัวอักษร `A` คู่ | **section** | ✅ เจอ |
| ไดเมนชั่นธรรมดา — ลูกศรชี้เข้าหากัน ไม่มีตัวอักษรคู่ | ไม่ใช่ section | ✅ ไม่เจอ |
| ตัวอักษร `B` คู่ห่างกันไกล แต่**ไม่มีหัวลูกศรเลย** | ไม่ใช่ section | ✅ ไม่เจอ |
| หัวลูกศร 2 อันชี้ทางเดียวกัน แต่**ไม่มีตัวอักษรคู่** | ไม่ใช่ section | ✅ ไม่เจอ |

ผลรวม: **เจอ marker 1 ตัว และเป็นตัวจริง** (`t_classify.js`)

### 1b.4c เมื่อไฟล์ไม่ประกาศอะไรเลย — สร้างขึ้นใหม่จากรูปทรง

แบบจำนวนมากมาถึงในสภาพ **ไม่มี entity `DIMENSION` เลยแม้แต่ตัวเดียว** (export แบบ
exploded หรือมาจากโปรแกรมที่เขียนแต่เรขาคณิต) มีแต่เส้น · สามเหลี่ยมทึบ · และตัวเลข
STYLIZE จึงไม่มีอะไรให้แก้

**จุดยึดคือ "ตัวเลข"** — ตัวเลขบนแบบไม่ใช่ของประดับ มันคือป้ายของการวัด
และสิ่งที่ถูกวัดอยู่ข้าง ๆ มันเสมอ

| เจอ | นับเป็น | เกณฑ์ที่ต้องผ่านครบ |
|---|---|---|
| หัวลูกศร 2 อัน **หันเข้าหากันบนแนวเดียว** + ตัวเลขอยู่ข้าง ๆ | linear | ทิศตรงข้าม (dot < −0.9) · แนวเชื่อมขนานกับทิศลูกศร · **ระยะระหว่างปลาย = ตัวเลขที่แบบระบุ** |
| หัวลูกศร 1 อัน **ปลายอยู่บนวงกลม/ส่วนโค้งจริง** + ตัวเลขขึ้นต้น `R` | radius | ปลายห่างจากขอบวง < 0.4 mm · **รัศมีวงนั้น = ตัวเลขที่ระบุ** |
| เหมือนข้างบน แต่ตัวเลขมี `⌀` | diameter | **2 × รัศมีวงนั้น = ตัวเลขที่ระบุ** |
| อย่างอื่น | ไม่แตะ | บันทึกเหตุผลไว้ใน `recoverReport` ให้ตรวจสอบได้ |

**กฎที่สำคัญที่สุดคือข้อสุดท้ายของแต่ละแถว: เรขาคณิตต้องตรงกับตัวเลขที่แบบเขียนไว้**
ไม่มีอย่างอื่นแยกคู่ลูกศรจริงออกจากลูกศรสองอันที่บังเอิญเรียงกันได้
ก่อนใส่เกณฑ์นี้ ระบบสร้างไดเมนชั่นปลอมขนาด 36.03 และ 38.97 mm ที่แบบไม่เคยมี

**การจับคู่ทำแบบ "เสนอทั้งหมดก่อน แล้วรับตัวที่พอดีที่สุดก่อน"**
ไม่ใช่ตัดสินทีละตัวเลขตามลำดับที่อ่านเจอ — มิฉะนั้นตัวเลขที่อ่านก่อนจะแย่งหัวลูกศร
ที่เข้ากับตัวเลขอื่นได้ดีกว่าไป

ระยะเว้น · ระยะยื่น · ขนาดหัวลูกศร **ไม่เดาจาก dimstyle แต่วัดจากเส้นที่ไฟล์วาดจริง**

### A1. ไดเมนชั่นแนวเส้นตรง (linear · aligned)

| เจอ | ต้องเป็น |
|---|---|
| เส้นฉาย | เว้นจากชิ้นงานตามที่ไฟล์เว้น · **ยื่นเลยเส้นบอกระยะเสมอ** (จึงบรรจบกันแน่นอน) |
| ระยะเว้นกว้างกว่าระยะถึงเส้นบอกระยะ | ย่อระยะเว้นลง — เส้นฉายที่สั้นกว่าเส้นบอกระยะคือความผิดพลาด ต้องเป็นไปไม่ได้ |
| ตัวเลขอยู่ระหว่างเส้นฉาย | **รูปแบบใน** — หัวลูกศรอยู่ใน ปลายจรดเส้นฉาย ชี้ออก · ไม่มีเส้นเลยออกไป |
| ตัวเลขอยู่นอกเส้นฉาย | **รูปแบบนอก** — หัวลูกศรพลิกออก · เส้นยื่นออกไปรับตัวเลข |
| **ตัวเลขที่แสดง** | **วัดจากเรขาคณิต แล้วจัดทศนิยมตาม Format Config** — ส่วนที่ห่อหุ้ม (`2x`, `⌀`, `R`, โน้ต) เก็บไว้ ตัวเลขเองไม่เคยถูกตรึง |
| ตัวเลข | จัดกึ่งกลางเส้นบอกระยะ (หรือกึ่งกลาง jog เมื่อรูปแบบนอก) · **ห่างจากเส้น 4 px วัดถึงหมึกจริง** |
| หัวลูกศร | เป็น cap ของเส้น ไม่ใช่ชิ้นแยก · สัดส่วน 3:1 |

**ตัวตัดสินรูปแบบมีข้อเดียว:** ตัวเลขอยู่ระหว่างเส้นฉายหรือไม่ — ไม่ต้องมีเงื่อนไขอื่น

### A2. รัศมี (radius) และเส้นผ่านศูนย์กลาง (diameter)

| เจอ | ต้องเป็น |
|---|---|
| ชนิด radius | ศูนย์กลาง = กลุ่ม 10 · รัศมี = ระยะถึงกลุ่ม 15 |
| ชนิด diameter | **ศูนย์กลาง = กึ่งกลางของกลุ่ม 10 กับ 15** · รัศมี = ครึ่งหนึ่ง |
| หัวลูกศร | **ตั้งอยู่นอกวง · ปลายแตะส่วนโค้ง · ชี้เข้าหาจุดศูนย์กลาง** |
| จำนวนเส้นที่ลาก | **ฝั่งเดียว — ฝั่งที่มีตัวเลข** ไม่ลากข้ามไปอีกฝั่ง |
| จุดศูนย์กลาง | เครื่องหมาย `+` ขนาดอย่างน้อย 0.9 mm ต่อแขน · มีเส้นลากจากส่วนโค้งไปถึง |
| ศูนย์กลางอยู่ไกลจนไม่มีที่ | **ย่อฟันปลา** — ช่วงติดหัวลูกศรยังอยู่บนแนวรัศมีจริง · `+` ไปที่ศูนย์กลางสมมติ · **ค่าที่แสดงยังเป็นรัศมีจริง** |
| ตัวเลข | อยู่บน landing แนวนอน · ห่าง 4 px · landing ยืดไปรับตัวเลขเสมอ |

## 3. หมวด B — เครื่องหมายหน้าตัด (section)

### B0. หาให้เจอจาก "รูปร่าง" ไม่ใช่ "ชื่อเลเยอร์"

ลายเซ็นที่ annotation อื่นไม่มี:
**หัวลูกศร 2 อันชี้ไปทางเดียวกัน · วางบนแนวที่ตั้งฉากกับทิศนั้น · มีตัวอักษรคู่กันข้าง ๆ**

ส่วนตัวอักษรโซนของกรอบกระดาษ A–D/1–6 ก็ไม่มีหัวลูกศรคู่)

| เจอ | ต้องเป็น |
|---|---|
| ทิศการมอง | **ยอดสามเหลี่ยม ลบ กึ่งกลางฐาน** ของหัวลูกศรเดิม — อ่านครั้งเดียว **ห้ามคำนวณใหม่** เพราะกลับทิศ = ความหมายเปลี่ยน |
| ชนิดของเส้นตัด | **เส้น phantom** (ยาว-จุด-จุด) ตาม ISO 128 · เส้นทึบจะอ่านเป็นขอบชิ้นงาน |
| เส้นตัด + แขน + หัวลูกศร (เดิมแยกกันหลายท่อน) | **polyline เดียว 4 จุด**: ขาออก → หักศอก → ตลอดเส้นตัด → หักศอก → ขาออก · หัวลูกศรเป็น cap ที่ปลายทั้งสอง |
| ชิ้นส่วนเดิมของ marker | **ลบทิ้งให้หมด** ทั้งเส้น 2 จุด · รูปปิด (หัวลูกศรที่วาดเป็นโพลีไลน์) · SOLID |
| เส้นที่อยู่ในแนวเดียวกันแต่ไม่ใช่ของ marker | **อ่านได้ ห้ามลบ** — เส้นศูนย์กลางของชิ้นงานมักทับแนวเส้นตัด |
| ตัวอักษร | **เลยหัวลูกศรไปตามทิศการมอง** · ห่าง 4 px วัดถึงหมึกจริง · ใหญ่กว่าตัวเลขไดเมนชั่น 1.4 เท่า (ISO 128) |
| การจัดกลุ่ม | เส้น + ตัวอักษรเป็นชิ้นเดียวกัน คลิกทีเดียวได้ทั้งชุด |

ตัวอ่านทั่วไป (รวมทั้ง ezdxf และตัวอ่านของแอปเอง) จึงแสดงมันเป็นตัวหนังสือดิบ ๆ
แก้เป็น **control code ของ DXF เอง**: `%%c` (⌀) · `%%d` (°) · `%%p` (±)
ซึ่งเป็นมาตรฐานมาตั้งแต่ R12 และตัวอ่านของแอปก็ถอดรหัสได้อยู่แล้ว

ทุกการทดสอบก่อนหน้านี้ผ่านหมด เพราะไม่มีตัวไหน **เปิดไฟล์ที่ตัวเองเขียนแล้วดูตัวหนังสือ**

## 5e. ทำไมคุณถึงเห็นว่า "ไม่มีอะไรถูกแก้"

ทุกการทดสอบของผมเริ่มจาก **เบราว์เซอร์เปล่า** แล้ว import ไฟล์ใหม่ทุกครั้ง
ผู้ใช้จริงไม่ได้ทำแบบนั้น — เปิดไฟล์เวอร์ชันใหม่ในเบราว์เซอร์เดิม
แล้ว**กดเข้าโปรเจกต์ที่บันทึกไว้** ซึ่งไม่มีการอ่าน DXF ใหม่เลย

ทดสอบตามเส้นทางนั้นจริง (`t_stale.js`):

| | ผล |
|---|---|
| ทำงานในบิลด์เก่า แล้วบันทึก | โปรเจกต์ถูกเก็บพร้อมเส้นทั้งหมด แต่ **ไม่มีโมเดลเลย** |
| เปิดบิลด์ใหม่ กดเข้าโปรเจกต์เดิม | **โมเดล 0 ตัว** |
| กด STYLIZE | **ไม่มีอะไรเปลี่ยน** — เพราะไม่มีโมเดลให้จัดรูปแบบ |
| ทศนิยม | ไม่เปลี่ยนตามที่ตั้ง |

**นี่คือคำอธิบายทั้งหมดของ "ปัญหาทุกอย่างยังเหมือนเดิม"** ไม่ใช่ว่ากฎไม่ทำงาน
แต่ไม่มีอะไรให้กฎทำงานด้วยเลย

### แก้: โปรเจกต์ที่เปิดขึ้นมาถูกทำให้ทันสมัยก่อน

ตอนกดเข้าโปรเจกต์ ระบบจะ:
1. **เติมช่องที่โมเดลรุ่นใหม่ต้องใช้** ให้โมเดลเก่า และแยกตัวเลขออกจากส่วนที่ห่อหุ้ม
   เพื่อให้ทศนิยมกลับมาเป็นสิ่งที่คำนวณได้
2. **หาวงกลมคืนจากโพลีไลน์** — บิลด์เก่าไม่ได้จำว่าเส้นไหนเคยเป็นวงกลม
   จึงไม่มีอะไรให้รัศมีตรวจสอบตัวเอง ใช้การ fit วงกลมจากจุดที่วาดจริง (คลาด ≤ 0.02 mm)
3. **สร้างโมเดลขึ้นใหม่จากเส้นที่มีอยู่** ด้วยกฎ §1b.4c — แบบเก่ามีลูกศร เส้น และตัวเลขครบ
   ซึ่งเป็นสิ่งเดียวกับที่ตัวสร้างคืนอ่าน

| หลังแก้ | ผล |
|---|---|
| โปรเจกต์เก่าเปิดขึ้นมา | **สร้างโมเดลคืนได้ 32 จาก 33** (linear 20 · radius 7 · ⌀ 5) + section 1 |
| วงกลมที่หาคืนได้ | **78 วง** |
| ทศนิยมตามที่ตั้ง | **ตรงทุกตัวที่มีโมเดล** |
| ที่ยังไม่ได้ | ค่า `13.45` หนึ่งตัว — รายงานไว้ตรง ๆ ไม่ได้ปัดเป็นผ่าน |

**บทเรียน:** ผมทดสอบแต่ "ผู้ใช้ที่เริ่มจากศูนย์" มาตลอด ทั้งที่คนที่เจอปัญหาคือ
"ผู้ใช้ที่มีงานเก่าอยู่แล้ว" — เส้นทางที่ต่างกันคนละเรื่อง

## 5f. Add Text — หัวเรื่องที่ผู้ใช้เพิ่มเอง

กฎเดียวเก็บไว้ที่เดียว แล้วใช้ร่วมกันทั้งตอนวาด · ตอนพิมพ์ · และตอน export

| พิมพ์ `section a-a` ตอนแผ่นตั้ง 14 pt | ได้ **`SECTION A-A`** · **หนา** · **5.6444 mm = 16 pt** ✅ |

ธงจึงหล่นหายที่ขั้นตอนเดียวที่ลงหมึกจริงบนหน้ากระดาษ
ถ้าดูแค่ค่าในโมเดลจะผ่านทุกข้อ

## 5g. ลูกศรชี้พร้อมหมายเลข (Item balloon)

ปุ่มใหม่ **①** บนแถบเครื่องมือ ข้าง ๆ ปุ่มข้อความ

สร้างเป็น **โมเดล** เหมือนทุกอย่างในเอกสารนี้ — เก็บแค่ข้อเท็จจริง 3 อย่าง
แล้วคำนวณเส้นทุกเส้นจากมัน:

| เก็บ | คำนวณจากมัน |
|---|---|
| `num` หมายเลข | ขนาดวงกลม (โตตามความกว้างของเลข) · ตัวเลขกลางวง |
| `c` จุดศูนย์กลางวง | จุดเริ่มเส้นชี้ = ขอบวง |
| `tip` ปลายที่ชี้ชิ้นงาน | ทิศเส้นชี้ · หัวลูกศรที่ปลาย |

**เส้นชี้จึงหลุดจากวงกลมไม่ได้ และหัวลูกศรหลุดจากปลายเส้นไม่ได้** เพราะไม่มีอันไหน
ถูกเก็บแยกจากโมเดล

| การวัด (กดปุ่มจริง) | ผล |
|---|---|
| กด 2 ครั้ง | ได้ 2 อัน เลข `1` และ `2` เรียงกันไม่ทับ |
| ชิ้นส่วนต่อหนึ่งอัน | วงกลม 1 · เส้นชี้ 1 · หมายเลข 1 · หัวลูกศรที่ปลาย 1 |
| แก้เลข `1` → `12` | **วงกลมโตจาก 3.20 เป็น 4.40 mm เอง** |
| **ลากปลายลูกศร** | ตามเคอร์เซอร์คลาด **0.084 mm** |
| **ลากวงกลม** | ตามเคอร์เซอร์คลาด **0.090 mm** |
| เส้นชี้เริ่มบนขอบวงพอดี | **0.0000 mm** ทั้งสองการลาก |
| เส้นชี้จบที่ปลายลูกศรพอดี | **0.0000 mm** ทั้งสองการลาก |
| ในไฟล์ที่ export | **CIRCLE จริง** (ไม่ใช่รูปหลายเหลี่ยม) ล้อมหมายเลขไว้ · รัศมีตรง |

ดับเบิลคลิกที่หมายเลขเพื่อแก้ · หมายเลขเก็บอยู่ในโมเดล ไม่ใช่ในข้อความที่วาด
วงกลมจึงปรับขนาดตามเลขที่พิมพ์ทันที

## 5h. ตาราง BOM และการย้ายของ

### ขนาดตัวอักษรในตาราง

| | ขนาด |
|---|---|
| หัวเรื่อง **BILL OF MATERIAL** | **เท่ากับที่ตั้งใน Format Config** — มันเป็นชื่อของตาราง |
| หัวคอลัมน์ · เลขลำดับ · เนื้อในทุกช่อง | **เล็กกว่า 2 pt** — รายการชิ้นส่วนอ่านใกล้ ๆ ไม่ควรแย่งสายตาไปจากแบบ |

วัดที่ 10 pt: หัวเรื่อง 3.5278 mm · ในตาราง 2.8222 mm
วัดที่ 16 pt: หัวเรื่อง 5.6444 mm · ในตาราง 4.9389 mm — ตรงทั้งสองค่า
และหัวคอลัมน์ที่ยาวที่สุดยังพอดีช่อง (ล้น 0 mm)

### ตารางเป็น "ของชิ้นหนึ่ง" บนกระดาษ

เดิมเป็นกรณีพิเศษ: ลากได้ด้วยโค้ดของตัวเอง แต่**เลือกไม่ได้และลบไม่ได้เลย**
ตอนนี้คลิกที่ตารางแล้วถูกเลือกเหมือนของอื่น กด Delete แล้วหายไป
(ลากในตารางเพื่อย้าย และลากเส้นแบ่งคอลัมน์เพื่อปรับความกว้าง ยังทำได้เหมือนเดิม)

**บั๊กที่ขวางอยู่:** ตัวกันคลิกในแถบตารางชื่อแบบ ทิ้งคลิกทุกอันที่ไม่ได้ลงบนไดเมนชั่น
ตาราง BOM ที่วางอยู่ในแถบนั้นจึงคลิกไม่ติดเลย — คลิกไปไม่ถึงโค้ดที่เลือกมันด้วยซ้ำ

**และ:** ลบไดเมนชั่น/เครื่องหมายหน้าตัด/ลูกศรชี้ทิ้ง ตอนนี้ลบ**โมเดล**ของมันด้วย
ไม่งั้น STYLIZE จะวาดสิ่งที่ถูกลบไปแล้วกลับขึ้นมาอย่างซื่อสัตย์

### ย้ายทั้งก้อน

**สาเหตุที่ยังยกทั้งก้อนไม่ได้:** ทุกเส้นที่นำเข้ามาเป็น "วัตถุ" ของตัวเอง
ต้องลากกรอบคลุมทั้งร้อยกว่าชิ้นก่อนถึงจะย้ายได้

ตอนนี้**จัดกลุ่มเรขาคณิตที่นำเข้าตามวิว**ตั้งแต่ตอน import โดยรวมเส้นที่แตะกันหรือ
เกือบแตะกัน (ห่างไม่เกิน 2.5 mm) เข้าเป็นก้อนเดียว — **คลิกครั้งเดียวได้ทั้งวิว**
(ยังกด Ctrl+Shift+G แยกออกเป็นชิ้น ๆ ได้เหมือนเดิมถ้าต้องการงานละเอียด)

**แล้วเจอปัญหาต่อทันที:** พอย้ายวิว ไดเมนชั่นถูกทิ้งไว้ข้างหลัง ชี้ไปที่กระดาษเปล่า
เพราะไดเมนชั่นอยู่คนละกลุ่ม

กฎที่ใช้แก้: **งานอธิบายแบบเดินทางไปกับสิ่งที่มันอธิบาย แต่ไม่ใช่ในทางกลับกัน**
- ยกวิว → ไดเมนชั่น · เครื่องหมายหน้าตัด · ลูกศรชี้ ของวิวนั้นไปด้วยทั้งหมด
- คลิกไดเมนชั่น → ได้**เฉพาะไดเมนชั่นตัวนั้น** (4 ชิ้น) ยังแก้ทีละตัวได้เหมือนเดิม

ไดเมนชั่นรู้ว่าตัวเองอธิบายวิวไหน จาก**จุดที่มันวัด**ว่าตกอยู่ในวิวใด

| การวัด (เมาส์จริง) | ผล |
|---|---|
| import แล้วได้กี่กลุ่ม | 496 วัตถุ → **35 กลุ่ม** (วิวใหญ่สุด 312 ชิ้น) |
| **คลิกครั้งเดียวเลือกได้** | **496 ชิ้น** (ทั้งแบบพร้อมไดเมนชั่น) |
| ลากแล้วขยับจริง | **496 ชิ้น · 81,839 พิกเซลเปลี่ยน** |
| **คลิกไดเมนชั่นได้เฉพาะตัวมันเอง** | **4/4 ชิ้น** ✅ |

### ย้ายตำแหน่งหลัง import

**สาเหตุ:** จุดจับ (grip) ของไดเมนชั่นกินพื้นที่**ทั้งเส้น** ไม่ใช่แค่สี่เหลี่ยมเล็ก ๆ
ลากตรงไหนบนไดเมนชั่นก็กลายเป็นการเลื่อนตัวเลขแทนการย้าย

ตอนนี้**เฉพาะสี่เหลี่ยมจุดจับเท่านั้นที่ปรับรูปร่าง** ที่เหลือว่างไว้ให้ลากย้าย
(เส้นเข้าศูนย์กลางของรัศมียังจับได้ที่จุดกึ่งกลาง ซึ่งเป็นจุดจับ ไม่ใช่ทั้งเส้น)

วัดด้วย**เมาส์จริงและนับพิกเซลที่เปลี่ยน**: เส้นธรรมดา **18,420 พิกเซล** ·
ไดเมนชั่นทั้งชุด **1,364 พิกเซล** — ขยับจริงทั้งคู่

## 5i. สวิตช์ ANSI · พรีวิว · ปุ่ม Add Pointer

### สวิตช์ที่ทำงานจริง

**ANSI Radius ไม่ได้ต่อกับอะไรเลย** — มันเคยคุมโค้ดเดาที่ถูกลบไปแล้ว
ส่วนการวาดจากโมเดลทำงานตลอดไม่ว่าสวิตช์จะเปิดหรือปิด

ตอนนี้สวิตช์ทั้งสองคุมการวาดจากโมเดลของตัวเอง วัดผลด้วยการปิดสวิตช์
เปลี่ยนขนาดตัวอักษร แล้วกด STYLIZE:

| | ปิดแล้วไม่ถูกแตะ | เปิดแล้วจัดรูปแบบจริง |
|---|---|---|
| ANSI Radius | ✅ | ✅ |
| ANSI Section | ✅ | ✅ |

สีสวิตช์เปลี่ยนจากดำเป็นสีหลักของแอป `rgb(0,119,255)`

### พรีวิว — ต้นเหตุจริงของความเบลอ

ผมแก้เรื่องการย่อตามความกว้างไปรอบก่อน แต่**นั่นไม่ใช่สาเหตุของความเบลอ**

canvas กำหนดขนาดพื้นที่วาดจาก `clientWidth` **ตอนที่แผงเพิ่งถูกสร้าง** ซึ่งยังเป็น 0
เพราะเบราว์เซอร์ยังไม่ได้จัดหน้า โค้ดจึงตกไปใช้ค่าสำรอง 420 px แล้ว CSS ก็ยืดภาพนั้น
ไปเป็นความกว้างจริง (550 px) — **เป็นการยืดภาพ ไม่ใช่การวาดใหม่** จึงเบลอและสัดส่วนเพี้ยน
ตรงกับที่บอกว่า "เหมือนเป็นรูปแล้วถูกบีบขนาด"

แก้โดยรอจนกว่าจะมีความกว้างจริงก่อนวาด และเฝ้าดูการเปลี่ยนขนาดด้วย `ResizeObserver`
วัดผล: พื้นที่วาด 1100 px ÷ dpr 2 = 550 px = ความกว้าง CSS พอดี — **ไม่มีการยืดเลย**

### พรีวิว (ต่อ)

`previewScale` ย่อให้พอดีเฉพาะ**ความสูง** พอตั้งตัวอักษรใหญ่ ตัวอย่างจึงล้นออกนอกกรอบ
ทั้งสองข้างและดูเบลอ ๆ แปลก ๆ — ตอนนี้ย่อตาม**ความกว้าง**ด้วย
ทดสอบที่ 6 pt และ 18 pt: อยู่ในกรอบทั้งคู่

ข้อความใต้ช่อง Size เคยเขียนตายตัวว่า `10 pt ≈ 3.5 mm (ISO)` ไม่ว่าจะตั้งเท่าไร
ตอนนี้บอกค่าจริง เช่น `18 pt ≈ 6.35 mm · ISO 3098: 3.5 mm`

### สัญลักษณ์มุมฉายในตารางชื่อแบบ

เส้นที่ผ่ากรวยและกากบาทของเป้าคือ **เส้นศูนย์กลาง** — นั่นคือความหมายของมัน
จึงต้องวาดเป็นเส้นลูกโซ่ (ยาว-ช่อง-จุด-ช่อง) ไม่ใช่เส้นทึบ ส่วนรูปกรวยและวงกลม
ยังเป็นเส้นทึบตามเดิม และย่อสัญลักษณ์ทั้งชุดเหลือ **80%**

### ปุ่ม Add Pointer

เปลี่ยนชื่อฟีเจอร์เป็น **Add Pointer** และใช้ไอคอนเคอร์เซอร์ตามที่กำหนด
ใช้ไฟล์ `Mouse_pointer.svg` ที่ให้มาโดยตรง (เปลี่ยนสีเส้นเป็น `currentColor`
เพื่อให้ตามสีของปุ่ม) ฝังเป็น SVG ในหน้า ไม่พึ่งฟอนต์ไอคอน

## 5x. สวิตช์ ANSI ใน Format Config

สวิตช์สองตัวนี้ตัดสินว่า STYLIZE **แตะอะไรได้บ้าง**

| สวิตช์ | คุมอะไร |
|---|---|
| ANSI Radius Dimension | ไดเมนชั่นรัศมีและเส้นผ่านศูนย์กลาง |
| ANSI Section Dimension | เครื่องหมายหน้าตัด |

**ปิด ไม่ได้แปลว่า "ย้อนกลับ" แต่แปลว่า "ปล่อยไว้"** — สิ่งที่แบบมีอยู่คงเดิมทุกอย่าง

### เดิมมันไม่ได้ต่อกับอะไรเลย

สวิตช์เคยผูกกับโค้ดเดาจากรูปร่าง พอโค้ดนั้นถูกลบ สวิตช์ก็ยังอยู่ในแผงแต่**เลิกมีความหมาย** —
การวาดจากโมเดลทำงานตลอดไม่ว่าจะเปิดหรือปิด สวิตช์ที่ไม่ทำอะไรแย่กว่าไม่มีสวิตช์

### ตัววัด

`t_toggle.js` — ตั้งค่าโดยตรง แล้วเทียบว่าถูกแตะไหม
`t_toggleui.js` — **คลิกสวิตช์จริงในแผง** กด Save แล้วกด STYLIZE

| | คลิกแล้วปิดจริง | ปิดแล้วไม่ถูกแตะ | เปิดแล้วจัดรูปแบบจริง |
|---|---|---|---|
| ANSI Radius | ✅ | ✅ | ✅ |
| ANSI Section | ✅ | ✅ | ✅ |

**บทเรียนจากการวัดครั้งแรก:** ผมนับพิกเซลทั้งผ้าใบ แล้วได้ 25,385 พิกเซลขยับ "ทั้งที่ปิดอยู่"
— เพราะการเปลี่ยนขนาดตัวอักษรทำให้ไดเมนชั่น**ชนิดอื่น**ขยับด้วย
ตัววัดต้องดูเฉพาะงานอธิบายแบบที่สวิตช์นั้นคุม ไม่ใช่ทั้งหน้า

สีสวิตช์เปลี่ยนจาก `#111` เป็น `var(--ink)` — สีหลักของแอป `rgb(0,119,255)`
