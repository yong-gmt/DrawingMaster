# การวิเคราะห์ — ทุกต้นเหตุที่เจอในเซสชันนี้

เอกสารนี้ไม่ใช่รายการฟีเจอร์ แต่เป็นบันทึกว่า **อาการที่เห็นคืออะไร · ต้นเหตุจริงคืออะไร ·
รู้ได้อย่างไร** เพราะสิ่งที่มีค่าที่สุดจากเซสชันนี้ไม่ใช่โค้ด แต่เป็นวิธีที่ทำให้เจอต้นเหตุ

---

## 0. บทเรียนใหญ่ที่สุด 3 ข้อ

**1. อย่าถามโมเดลว่าตัวเองถูกไหม**

การทดสอบส่วนใหญ่ในช่วงแรกเรียกฟังก์ชันของโมเดลแล้วเทียบกับค่าในโมเดลเอง
มันเห็นด้วยกับตัวเองเสมอ บั๊กที่ผู้ใช้เห็นอยู่ใน**เส้นที่วาดออกมา** ไม่ใช่ในโครงสร้างข้อมูล

> ตัวอย่าง: STYLIZE เลิกจัดรูปแบบไดเมนชั่นไปทั้งรอบ เพราะบรรทัดที่เรียกโมเดลถูกลบไปพร้อมกับ
> โค้ดเก่า — เทสต์ 30 กว่าตัวผ่านหมด จนกระทั่งเขียนตัวที่ถามว่า
> "ตัวเลขที่วาดอยู่ ตรงกับที่โมเดลบอกไหม"

**2. ทดสอบผู้ใช้ที่มีของเก่าอยู่แล้ว ไม่ใช่แค่ผู้ใช้ใหม่**

บั๊กที่หนักที่สุดสองตัวเกิดกับคนที่ใช้งานมาสักพักแล้วเท่านั้น เทสต์ที่เปิดเบราว์เซอร์ใหม่เปล่า ๆ
ทุกครั้งมองไม่เห็นทั้งคู่ (ดู §8 และ §9)

**3. ถ้าอะไรดูผิด ให้ถ่ายภาพก่อนคิด**

หลายรอบเสียไปกับการให้เหตุผลเรื่องเรขาคณิตที่ภาพเดียวจบได้ใน 1 นาที
และบางครั้งภาพก็เป็นสิ่งเดียวที่จับบั๊กได้ เช่นตัวเลขซ้อนกันสองชั้นทั้งที่ทุกค่าวัดผ่านหมด

---

## 1. ไฟล์ที่ export ออกไปแก้ไขไม่ได้

**อาการ:** "มันควรออกมาเป็นแบบที่ไฟล์อื่นแก้ไขได้"

**ที่ผมทำผิด:** ไล่แก้การวาดบนหน้าจอมาหลายรอบโดย**ไม่เคยเปิดดูไฟล์ที่ export เลยสักครั้ง**

**ต้นเหตุ:** `exportDXF` ไล่ตามรอยที่วาดบนจอ แล้วเขียนออกมาเป็นเส้นดิบ

| ไฟล์ Head-back ที่เขียนออกไป | |
|---|---|
| LWPOLYLINE / SOLID / TEXT | 473 / 61 / 126 |
| **DIMENSION** | **0** |
| เลเยอร์ | มีแค่ `"0"` ทั้ง 660 ชิ้น |
| ตาราง LAYER / LTYPE / BLOCKS | ไม่มี |

**แก้:** เขียน DXF writer ใหม่ที่เผยแพร่ **โมเดล** ไม่ใช่รอยวาด — รูปแบบ AC1009 (R12)
พร้อมตาราง LAYER, LTYPE, BLOCK ต่อไดเมนชั่น และ DIMENSION entity ที่มี definition point

**วิธีตรวจที่ใช้ได้ผล:** import ไฟล์ที่ตัวเองเขียนกลับเข้ามา แล้วเทียบค่า
และให้ **ezdxf** (ไลบรารีที่ไม่เคยเห็นแอปนี้) อ่านและวัดเอง

---

## 2. วงกลมกลายเป็นรูปหลายเหลี่ยม

**ต้นเหตุ:** ตอน import แปลง ARC/CIRCLE เป็นโพลีไลน์แล้ว **ทิ้งข้อมูลวงกลม**
ตอน export จึงไม่มีอะไรให้เขียนกลับ

| | ต้นฉบับ | เดิม | หลังแก้ |
|---|---|---|---|
| CIRCLE | 17 | 0 | 17 · รัศมีตรง |
| ARC | 51 | 0 | 51 · รัศมีตรง |

**แก้:** จำ `{cx, cy, r, a0, a1}` ไว้ตั้งแต่ import

---

## 3. ส่วนโค้งเพี้ยน — มุมกวาดผิดถึง 180°

**อาการ:** วงกลมยังไม่ถูกต้อง เพี้ยน

**ต้นเหตุ:** คำนวณมุมเริ่ม/จบโดยเอามุมเดิม **บวกมุมหมุนของ transform**
ซึ่งถูกเฉพาะเมื่อ transform เป็นการหมุนล้วน ๆ บล็อกที่ **กลับด้าน (mirror)**
สลับทิศการกวาด — ผิด 43 เส้นใน Sheet1 และ 53 เส้นใน Sheet3

Head-back ไม่มีอาการเพราะบล็อกไม่กลับด้าน จึงไม่เห็นมาก่อน

**แก้:** เลิกคำนวณจาก transform อ่านมุมจาก**จุดที่วาดจริง** — จุดที่วาดออกมาโกหกเรื่องตัวเองไม่ได้

**บทเรียนย่อย:** ตัววัดตัวแรกถามว่า "ตัวเลขมุมตรงกันไหม" ซึ่งผิดคำถาม
ตัวที่ใช้ได้ถามว่า **"ส่วนโค้งที่กวาดทวนเข็มจาก a0 ไป a1 ครอบคลุมจุดที่วาดพอดีไหม"**

---

## 4. ทิศหัวลูกศรของรัศมี

**อาการ:** "ลากหัวลูกศรมั่ว ไม่ตรงตามหลักการเขียนแบบ" — ซ้ำหลายรอบ

**กฎที่ถูก:** หัวลูกศร**ตั้งอยู่นอกวง ปลายแตะส่วนโค้ง ชี้เข้าหาจุดศูนย์กลาง**
และลากเส้น**ฝั่งเดียว — ฝั่งที่มีตัวเลข**

ผมเดาผิดสองรอบ (ครั้งหนึ่งทำให้ชี้ออก โดยอ้างเหตุผลของตัวเองว่า "รัศมีวัดออกจากศูนย์กลาง")
จนผู้ใช้วาดภาพให้ดู

**บทเรียน:** ในเรื่องที่มีมาตรฐานกำกับ ควรขอภาพตัวอย่างตั้งแต่ต้น
อย่าอนุมานจากหลักการที่คิดเอง

**ตัววัด:** `t_radarrow.js` ตรวจหัวลูกศรทุกอันในทุกไฟล์ 3 ข้อ:
ปลายแตะส่วนโค้ง · ตัวอยู่นอกวง · ชี้เข้าหาศูนย์กลาง

---

## 5. เส้นชี้ยืดออกไปไกลไม่ได้

**ต้นเหตุ:** ข้อศอกหาจาก "จุดที่แนวรัศมีตัดกับระดับความสูงของตัวเลข" ซึ่งพุ่งไปไกลอนันต์
เมื่อรัศมีเกือบขนานแนวนอน ผมจึงใส่**เพดานจำกัด** ไว้กันเรื่องนั้น — แล้วเพดานนั้นเองที่ทำให้
ลากออกไปไกลไม่ได้

**แก้ที่ราก:** เก็บ **"ความยาวเส้นชี้"** เป็นค่าในโมเดล ไม่ใช่ไปหาจุดตัด
ความยาวเป็นเท่าไหร่ก็ได้ และไม่มีวันหาไม่เจอ เพดานจึงไม่จำเป็น

> รูปแบบที่เกิดซ้ำในโปรเจกต์นี้: **การใส่ค่าจำกัดเพื่อกันอาการหนึ่ง มักสร้างอีกอาการหนึ่ง**
> ถ้าต้องใส่ limit ให้ถามก่อนว่ากำลังปะสิ่งที่ควรแก้ที่โครงสร้างหรือเปล่า

---

## 6. ย้ายตำแหน่งไม่ได้

**สองต้นเหตุ ที่ผมแก้ทีละอันโดยคิดว่าจบแล้ว**

**(ก) จุดจับกินพื้นที่ทั้งเส้น** — ลากตรงไหนบนไดเมนชั่นก็กลายเป็นการเลื่อนตัวเลข
แก้ให้**เฉพาะสี่เหลี่ยมจุดจับเท่านั้นที่ปรับรูปร่าง**

**(ข) ทุกเส้นเป็น object ของตัวเอง** — ต้องลากกรอบคลุมร้อยกว่าชิ้นก่อนถึงจะย้ายได้
แก้โดย**จัดกลุ่มตามวิว**ตั้งแต่ import (รวมเส้นที่ห่างกันไม่เกิน 2.5 mm)

**แล้วเจอปัญหาที่สาม จากภาพ:** ย้ายวิวแล้ว **ไดเมนชั่นถูกทิ้งไว้ข้างหลัง**
ตัวเลขบอกว่าย้ายสำเร็จ 496 ชิ้น แต่ภาพบอกว่าแบบถูกฉีกออกจากกัน

**กฎที่ใช้แก้:** งานอธิบายแบบเดินทางไปกับสิ่งที่มันอธิบาย **แต่ไม่ใช่ในทางกลับกัน**

---

## 7. Import ทำมากเกินไป

**อาการ:** "import มาแล้วทุกอย่างพังเลย เหมือนแก้ทุกอย่างให้เสร็จสรรพ"

**ต้นเหตุ:** import วาดทับแบบทันที ทั้งไดเมนชั่นจาก entity และที่สร้างคืนจากเส้น

**หลักที่ควรยึด (กลายเป็นหลักคิดข้อ 0):** **นำเข้าคือแสดงไฟล์ ไม่ใช่แก้ไฟล์**
ถ้า import แก้ไปแล้วครึ่งหนึ่ง จะไม่มีทางบอกได้ว่าอะไรมาจากไฟล์และอะไรมาจากเรา

**ตัววัด `t_noghost.js`:** ถามตรง ๆ ว่า "หลัง import มีเส้นของเราบนกระดาษกี่เส้น" → ต้องเป็น 0

> ครั้งแรกที่แก้ ยังเหลือ 132 เส้น เพราะ `dimRelayout` วิ่งวาดทุกโมเดลอยู่ดี
> ถ้าวัดแค่จำนวนพิกเซลที่ต่างกันคงคิดว่าผ่านแล้ว

*(หมายเหตุ: การเปลี่ยนนี้ถูกถอดออกในบิลด์ปัจจุบันตามคำขอ ยังอยู่ใน `DM_B_experimental`)*

---

## 8. เปิดโปรเจกต์เก่าแล้วเหมือนไม่มีอะไรเปลี่ยน

**อาการ:** "ปัญหาทุกอย่างยังเหมือนเดิม ไม่เห็นมีอะไรถูกแก้เลย"

**ต้นเหตุ:** โปรเจกต์ที่บันทึกไว้เก็บ **โมเดล** ไว้ด้วย เปิดในบิลด์ใหม่แล้ว
**ไม่มีการอ่าน DXF ใหม่เลย** โปรเจกต์จากบิลด์เก่าจึงมีโมเดล 0 ตัว และ STYLIZE
ไม่มีอะไรให้จัดรูปแบบ

**นี่คือคำอธิบายทั้งหมด** ไม่ใช่ว่ากฎไม่ทำงาน แต่ไม่มีอะไรให้กฎทำงานด้วย

**แก้:** ตอนเปิดโปรเจกต์ (1) เติมช่องที่โมเดลรุ่นใหม่ต้องใช้ (2) **fit วงกลมคืนจากโพลีไลน์**
เพราะบิลด์เก่าไม่ได้จำ (3) สร้างโมเดลใหม่จากเส้นที่มี → กู้คืนได้ 32 จาก 33

**บทเรียน:** ผมทดสอบแต่ "ผู้ใช้ที่เริ่มจากศูนย์" มาตลอด ทั้งที่คนที่เจอปัญหาคือ
"ผู้ใช้ที่มีงานเก่าอยู่แล้ว"

## 9. หน้ากระดาษหายไป และประวัติไม่ถูกบันทึก

**อาการ:** import แล้วหน้ากระดาษหาย · ออกแล้วเข้าใหม่ไม่บันทึก · **เครื่องอื่นใช้ได้**

**วิธีที่นำไปสู่คำตอบ** — ตัดสมมติฐานด้วยการทดสอบ ไม่ใช่ด้วยการเดา:

| สมมติฐาน | ทดสอบ | ผล |
|---|---|---|
| storage เต็ม | ยัดจนเต็ม 4.5 MB แล้ว import | ไม่ใช่ |
| บันทึกไม่ได้ | บล็อก localStorage ให้โยน error | ไม่ใช่ |
| ข้อมูลที่บันทึกเสียหาย | ยัดข้อมูลเสีย 5 แบบ | ไม่ใช่ |
| **ใช้งานสะสมหลายโปรเจกต์** | **import ซ้ำ 12 ครั้งในเบราว์เซอร์เดียว** | **ใช่** |

คำตอบของผู้ใช้ 3 ข้อชี้ตรงกัน: ลบไฟล์แล้วยังเหมือนเดิม (ไม่ใช่ที่ไฟล์) ·
ไม่มี error สีแดง (โค้ดไม่พัง) · **incognito ใช้ได้** (incognito เริ่มจากพื้นที่ว่าง)

**ต้นเหตุ:** **56% ของทุกโปรเจกต์ที่บันทึกคือ "รายการ object"** ซึ่งสร้างขึ้นจากแบบอยู่แล้ว
และถูกสร้างใหม่ทุกครั้งที่เปิด — เก็บไปโดยไม่มีประโยชน์ จน localStorage เต็มโควตา 5 MB
หลังจากนั้นเบราว์เซอร์ปฏิเสธการเขียน**เงียบ ๆ**

| soak 12 import | เดิม | เลิกเก็บของที่สร้างคืนได้ | ย้ายไป IndexedDB |
|---|---|---|---|
| โปรเจกต์ที่เก็บได้ | 8/12 | 12/12 | **20/20** |
| พื้นที่ | 4.90 MB (เต็ม) | 3.85 MB | **2.9 จาก 238 MB** |

**แก้ขั้นสุดท้าย:** ย้ายไป **IndexedDB** — พื้นที่หลักร้อย MB, เขียนทีละโปรเจกต์
ไม่ใช่ทั้งก้อน, ย้ายของเก่าจาก localStorage ให้อัตโนมัติแล้วปล่อยพื้นที่ 5 MB คืน

## 10. ข้อผิดพลาดของผมที่ทำให้เสียเวลามากที่สุด

**ส่งไฟล์ชื่อเดิมทับไปเรื่อย ๆ** ผู้ใช้ไม่มีทางยืนยันได้เลยว่ากำลังเปิดตัวไหน
และผมไม่มีทางแยกได้ว่า "ยังเหมือนเดิม" แปลว่าแก้ไม่ตรงจุด หรือแปลว่ายังไม่ได้เห็นของใหม่

→ ตอนนี้ทุกบิลด์มี **build stamp** ที่ชื่อแท็บและใน console และตั้งชื่อไฟล์ไม่ซ้ำ

**รวมงานหลายเรื่องไว้ในรอบเดียว** toggle + ไอคอน + พรีวิว + สัญลักษณ์ + จังหวะ import
+ phantom line ปนกันหมด พอมีอันหนึ่งพัง แยกไม่ออกว่าเป็นอันไหน และย้อนกลับก็ลำบาก

**แก้สคริปต์ build ด้วยการลบตามเลขบรรทัด** แล้วลบผิดบล็อก build ล้มและได้ไฟล์เก่า
ถ้าเชื่อคำว่า "patched ok" อย่างเดียวคงส่งไฟล์เก่าไปอีกรอบ

## 11. ตัววัดที่คุ้มค่าที่สุด

| ตัววัด | จับอะไรได้ |
|---|---|
| `t_objdmg.js` | เส้นวัตถุถูกแตะกี่เส้น — จับตอนลบเส้นศูนย์กลางจริงไป 14 เส้น |
| `t_extern.js` | ให้ ezdxf อ่านไฟล์ที่เราเขียนแล้ววัดเอง |
| `t_bold.js` | วัด**ความเข้มหมึกบนผ้าใบ** — จับธง bold ที่หล่นหายตอนวาด ทั้งที่โมเดลถูก |
| `t_manyproj.js` | import ซ้ำ 12 ครั้ง — จับ storage เต็ม |
| `t_stale.js` | เปิดโปรเจกต์ที่บันทึกด้วยบิลด์เก่า |
| `t_classify.js` | ไฟล์ที่มีตัวล่อ 3 แบบ — เกณฑ์ต้อง**ปฏิเสธ**ได้ ไม่ใช่รับอย่างเดียว |
| `t_ui.js` | กดปุ่มจริงทุกขั้น แล้วตัดสินไฟล์ที่โหลดมาด้วย ezdxf |

**สังเกต:** ตัวที่จับบั๊กได้จริงเกือบทั้งหมด**วัดสิ่งที่อยู่นอกโมเดล** — พิกเซล ไฟล์ที่เขียนออกไป
หรือสถานะของเบราว์เซอร์
