# สรุปสถานะปัจจุบัน

ไฟล์ที่ใช้งาน: **`build/DrawingMaster.html`** (ประกอบด้วย `scripts/build.py` แล้วตามด้วย `scripts/artwork.py`)
ชื่อแท็บจะบอก build stamp ไว้ ใช้ยืนยันว่าเปิดถูกไฟล์

## 1. ทำอะไรได้บ้าง

### อ่านแบบ

- นำเข้า DXF · **หลายไฟล์ต่อหนึ่งหน้ากระดาษ** — ไฟล์ถัดไปวางต่อทางขวา ไม่ทับของเดิม
- **นำเข้าแล้วแสดงไฟล์ตามที่เจ้าของวาดไว้ทุกเส้น** ไม่แก้อะไรจนกว่าจะกด STYLIZE
- อ่านเป็นโมเดล: ไดเมนชั่น (เส้นตรง · เอียง · รัศมี · เส้นผ่านศูนย์กลาง · **องศา**) · เครื่องหมายหน้าตัด · ลายตัด
- **สร้างไดเมนชั่นคืนจากแบบที่ไม่ประกาศอะไรเลย** — วัดกับ 3 ไฟล์ที่มีจำนวนต่างกัน (ข้อ 3)

### ไดเมนชั่นองศา

- อ่านมุมจากเส้นสองเส้นที่ไฟล์ระบุ · ทดสอบกับ **9 รูปแบบ** (มุมฉาก แหลม ป้าน เล็กมาก
  เกือบตรง สะท้อนกลับ กวาดตามเข็ม จุดยอดนอกเส้น ปลายผสม) **ถูกทั้งหมด**
- ตัวเลขเกาะเส้นโค้ง เอียงตามแนวสัมผัส มีเครื่องหมายองศา ระยะห่าง 4 px เท่าไดเมนชั่นอื่น
- ลากส่วนโค้งเข้าออกได้ · ลากตัวเลขไปรอบเส้นโค้งได้ · มุมไม่เปลี่ยน
- หัวลูกศรออกไปอยู่นอกเมื่อที่ว่างไม่พอ และเก็บกลับเมื่อลากตัวเลขกลับเข้ามา

### จัดรูปแบบ

- **STYLIZE** — จัดไดเมนชั่นและเครื่องหมายหน้าตัดให้เป็นแบบ ANSI/ISO (รายละเอียดข้อ 2)
- **สวิตช์เดียว** — เปิด: จัดให้ครบ · ปิด: เปลี่ยนเฉพาะขนาดตัวอักษร
- Format Config: ขนาดกระดาษ · ระยะขอบ · ฟอนต์ (Arial · Sarabun · Consolas) · ขนาดตัวอักษร · ทศนิยม · ความหนาเส้น

### แก้ไขบนกระดาษ

- คลิกเลือก · ลากย้าย · ลากกรอบเลือกหลายชิ้น · Ctrl+Shift+G จัดกลุ่ม
- **Shift ค้าง = ล็อกแกน** ตามจุดกึ่งกลางของสิ่งที่เลือก ไม่ว่าจะเลือกกี่ชิ้น
- จุดจับของไดเมนชั่น: ลากเส้นบอกระยะ · ตัวเลข · ปลายเส้นฉาย · เส้นชี้รัศมี
- **Add Text** — ตัวพิมพ์ใหญ่ · ตัวหนา · ใหญ่กว่าที่ตั้งไว้ 2 pt
- **Add Pointer** — ลูกศรชี้พร้อมหมายเลข แก้เลขได้ วงกลมโตตามเลข ลากได้ทั้งสองปลาย
- **BOM** — ตารางรายการชิ้นส่วน เลือกและลบได้ ตัวอักษรเล็กกว่าที่ตั้งไว้ 2 pt ยกเว้นหัวเรื่อง
- **ลบแล้วลบเลย** — ไม่กลับมาเมื่อเปิดโปรแกรมใหม่

### หน้าตา

- Line style 4 แบบพร้อมตัวอย่างเส้นจริง (object · hidden · center · phantom)
- หน้า Description มีตัวอย่างเส้น 5 แถว
- ตารางชื่อแบบใช้**อาร์ตเวิร์กจริง**: สัญลักษณ์มุมฉายจาก SVG (เว้นขอบ 1 mm) และโลโก้เต็มช่อง
- BOM ทุกแถวรวมหัวตาราง เว้นบนล่าง 4 px
- Stroke Weight มีผลกับทั้งเส้นวัตถุและเส้นไดเมนชั่น (บางสุดถึงหนาสุด 12 เท่า)
- ปุ่มเฟืองหน้ารวมโปรเจกต์ = ตั้งค่าเริ่มต้นของโปรเจกต์ใหม่ ไม่แตะโปรเจกต์เดิม
- ทั้งแอปเป็นภาษาอังกฤษ

### ส่งออก

- **DXF ที่แก้ไขได้จริง** — DIMENSION entity พร้อม definition point · ตาราง LAYER และ LTYPE ·
  CIRCLE/ARC ของจริง · ค่าเป็น `<>` ให้ปลายทางวัดเอง · สัญลักษณ์เป็น control code (`%%c` `%%d` `%%p`)
- PDF

### เก็บงาน

- **IndexedDB** — พื้นที่หลักร้อย MB (localStorage เดิมมี 5 MB แล้วเงียบเมื่อเต็ม)
- ย้ายของเก่าจาก localStorage ให้อัตโนมัติครั้งแรกที่เปิด
- **บันทึกทุกอย่างที่ทำ** — ปิดโปรแกรมแล้วเปิดใหม่ได้ภาพเดิม ไม่ต้องกด STYLIZE ซ้ำ

## 2. STYLIZE ทำงานอย่างไร

### หลักคิด 5 ข้อ

**0 — นำเข้าคือแสดงไฟล์ ไม่ใช่แก้ไฟล์**
ตอน import ระบบอ่านทุกอย่างเป็นโมเดล แต่ไม่วาดทับอะไรเลย
*วัดแล้ว: ภาพหลัง import ต่างจากตัวอ่านที่ไม่แก้อะไร **0 พิกเซล***

**1 — วาดจากโมเดล ไม่ใช่นวดเส้นเดิม**
ทุกเส้นคำนวณจากข้อเท็จจริงที่ไฟล์ยืนยัน กดกี่ครั้งก็ได้ผลเดิม
*วัดแล้ว: กดซ้ำ drift **0***

**2 — ไม่แตะเนื้อแบบ**
งานอธิบายแบบเขียนใหม่ได้ · เส้นวัตถุ กรอบกระดาษ ตารางชื่อแบบ ห้ามแตะ
*วัดแล้ว: เส้นวัตถุที่หายไป **0***

**3 — อ่านไม่ออกก็ปล่อยไว้**
โมเดลที่วาดทับของเดิมคลาดเกิน 0.35 mm ถือว่าอ่านผิด ปล่อยเส้นเดิมไว้

**4 — "แบบ" คือความจริง "รายการ object" เป็นมุมมองที่ทิ้งได้**
อะไรที่สร้างขึ้นใหม่ต้องใส่ลงในแบบเสมอ ไม่งั้นหายตอนเปิดโปรแกรมใหม่

### ลูปการทำงาน

```
กด STYLIZE:
  0. ถ้าสวิตช์ปิด → ข้ามไปข้อ 4 (เปลี่ยนเฉพาะขนาดตัวอักษร)
  1. รับช่วงเส้นของไฟล์ สำหรับโมเดลที่ยังรออยู่ตั้งแต่ import
  ทำซ้ำ (สูงสุด 6 รอบ):
     2. สแกนหาไดเมนชั่นที่ยังไม่มีโมเดล → สร้างคืนจากเส้น
     3. วาดทุกโมเดล — ไดเมนชั่น · หน้าตัด · ลูกศรชี้
        ถ้ารอบนี้ไม่เจอของใหม่ → ออกจากลูป
  4. ขนาดตัวอักษร: ทุกตัวที่ไม่ใช่กรอบกระดาษ จบที่ขนาดที่ตั้งไว้ (พาสเดียว รับประกัน)
  5. รายงานสิ่งที่ยังจับคู่ไม่ได้ พร้อมเหตุผล
```

### ไดเมนชั่น

| | |
|---|---|
| เก็บ | จุดที่วัด · ทิศ · ศูนย์กลาง · รัศมี — ข้อเท็จจริงที่ไฟล์ยืนยัน |
| ตัวเลข | **วัดจากเรขาคณิต** แล้วจัดทศนิยมตาม Format Config · ส่วนที่ห่อหุ้ม (`2x` `⌀` `R`) เก็บไว้ |
| เส้นบอกระยะ · เส้นฉาย · หัวลูกศร | คำนวณจากโมเดลทั้งหมด |
| รัศมี/⌀ | หัวลูกศรอยู่**นอกส่วนโค้ง ปลายแตะเส้น ชี้เข้าหาศูนย์กลาง** ฝั่งเดียว |
| ตัวเลขติดเส้น | ห่างคงที่ 4 px ทุกระดับซูม |

### เครื่องหมายหน้าตัด

ระบุจาก**รูปร่าง ไม่ใช่ชื่อเลเยอร์** — หัวลูกศร 2 อันชี้ทางเดียวกัน · ห่างกันพอ · ตั้งฉากกับทิศมอง · มีตัวอักษรคู่ใกล้ปลาย

| | |
|---|---|
| **หัวลูกศรของไดเมนชั่นไม่มีวันเป็นของ marker** | กฎนี้แก้อาการเส้นเอียงและหันผิดทิศ |
| แกนเส้นตัด | **ตั้งฉากกับทิศที่มอง** เสมอ — เอียงไม่ได้ |
| ชนิดเส้น | **phantom line** (ยาว–จุด–จุด) ตาม ISO 128 |
| ทิศการมอง | อ่านจากไฟล์ ไม่คำนวณใหม่ |
| ตัวอักษร | ตั้งตรง ใหญ่กว่าค่าที่ตั้ง 1.4 เท่า อยู่เลยปลายลูกศร |
| ของเก่า | หัวลูกศรและเส้นเดิมถูกยึดและลบออกจากแบบ · เส้นศูนย์กลางที่ทับแนวตัดถูกบัง (ไม่ลบ) |

### ข้อความ

| | ขนาด |
|---|---|
| ค่าไดเมนชั่น · โน้ต · ชื่อวิว | ตามที่ตั้งใน Format Config |
| ตัวอักษรหน้าตัด | × 1.4 |
| ข้อความที่ผู้ใช้เพิ่ม | + 2 pt · ตัวหนา · ตัวพิมพ์ใหญ่ |
| ตาราง BOM | − 2 pt (ยกเว้นหัวเรื่อง) |
| กรอบกระดาษ · ตารางชื่อแบบ | **ไม่แตะ** |

## 3. ความน่าเชื่อถือ — วัดแล้ว ไม่ใช่ความรู้สึก

**87 เทสต์** ทุกตัวขับเบราว์เซอร์จริงและ **วัด** ไม่ใช่แค่ผ่าน/ไม่ผ่าน

| ตัวที่ต้องเป็นศูนย์เสมอ | |
|---|---|
| เส้นวัตถุที่หายไป | **0** |
| กด STYLIZE ซ้ำแล้ว drift | **0** |
| import ต่างจากไฟล์ต้นฉบับ | **0 พิกเซล** |
| ปิดโปรแกรมแล้วเปิดใหม่ | เส้นหาย **0** · ขยับมากสุด **0.023 mm** |
| ค่าที่ถูกตรึงเป็นข้อความในไฟล์ export | **0** |

**สร้างไดเมนชั่นคืนจากเรขาคณิตล้วน** (`t_recover2.js` · `t_recoverhonest.js`)
ระเบิด DIMENSION ทิ้งจากทั้งสามไฟล์ แล้ววัดสองอย่าง: ได้ครบไหม และที่ได้ถูกไหม

| | ไดเมนชั่นในไฟล์ | สร้างคืนได้ | ไม่เจอ | ของปลอม | **ค่าไม่ตรงกับที่วัดได้** |
|---|---|---|---|---|---|
| Sheet1 | 11 | **11** | 0 | 0 | **0** |
| Head-back | 33 | **33** | 0 | 0 | **0** |
| Sheet3 | 43 | **39** | **4** | 0 | **0** |

Sheet3 ยังขาด 4 ตัว (`0.38 · 2.5 · 10.34 · 15.2`) **แต่ไม่มีของปลอมเลย** และทุกตัวที่สร้างคืนได้
วัดได้ตรงกับค่าที่มันแสดง

**สาเหตุที่ขาดไม่ใช่ความหนาแน่น** แต่เป็นการแย่งหัวลูกศร — เมื่อไดเมนชั่นถูกระเบิดเป็นเส้นเปล่า
ไม่มีป้ายบอกว่าหัวลูกศรอันไหนเป็นของใคร เครื่องหมายหน้าตัดจึงยึดหัวลูกศรของไดเมนชั่นที่บังเอิญ
ยืนบนแนวเส้นตัดเดียวกันไป แก้ไปแล้วสองชั้น (marker ยึดได้เฉพาะอันที่อยู่บนแนวเส้นและอันที่ใกล้ปลาย
ที่สุดเท่านั้น · หัวลูกศรที่ใช้ร่วมกันในชุดต่อเนื่องให้ใช้ได้สองไดเมนชั่น) — จาก 36 เป็น 39
ที่เหลืออีก 4 ยังเป็นการแย่งชนิดเดียวกัน

**ไดเมนชั่นองศา** (`t_angledetect.js`) — สร้างไฟล์ที่มีองศา 9 แบบที่ไฟล์ตัวอย่างไม่มี:
มุมฉาก · แหลม · ป้าน · เล็กมาก (7°) · เกือบตรง (175°) · **สะท้อนกลับ (240°)** ·
กวาดตามเข็ม · จุดยอดอยู่นอกเส้นที่วัด · ปลายผสม

**อ่านถูกทั้ง 9 แบบ** และไฟล์จริง 22° ยังถูก · ทุกค่ามีเครื่องหมายองศา ·
ลากส่วนโค้งเข้าออกได้ · ลากตัวเลขไปรอบส่วนโค้งได้ · **มุมไม่เปลี่ยนเมื่อลาก**

**ทดสอบกับไฟล์ที่พลิกแพลง** (`t_variants.js`) — หมุน 30° · หมุน 90° · กลับด้าน · ขยาย 2.5× · ย่อ 0.25×
ทั้ง 6 แบบให้คำตอบเดียวกัน: ไดเมนชั่น 33/33 · marker 1/1 · ขนาดผิด 0 · ซ้ำซ้อน 0

## 4. ที่ยังทำไม่ได้ — บอกตรง ๆ

| | |
|---|---|

| **SPLINE / ELLIPSE** | export ออกไปเป็นโพลีไลน์ |
| **BLOCK/INSERT** | ถูกแตกเป็นสำเนาตอน export |
| **แบบที่กลับด้าน** | โมเดลจาก entity สอบตก 7 ตัว (รอดเพราะตัวสร้างคืนเก็บมาแทน — เป็นจุดอ่อนที่ยังไม่ได้แก้ที่ราก) |
| **หัวคอลัมน์ BOM** | ล้นช่องเมื่อตั้งตัวอักษรเกิน ~14 pt |

**และข้อสำคัญที่สุด:** กฎทั้งหมดยืนอยู่บน **ไฟล์จริง 3 ไฟล์จาก 2 โปรแกรม**
เกือบทุกครั้งที่มีไฟล์ใหม่เข้ามาในเซสชันนี้ มีอย่างน้อยหนึ่งสมมติฐานพัง
ทุกไฟล์ที่ส่งมาเพิ่มจะกลายเป็นเทสต์ถาวร และเป็นวิธีเดียวที่จะทำให้มั่นใจได้จริง

## 5. เครื่องมือตรวจเมื่อเจอไฟล์แปลก

กด F12 → Console:

```js
__hook().textReport()   // ตัวอักษรทุกตัว: ขนาด · เลเยอร์ · ระบบมองเป็นอะไร · ได้ขนาดที่ต้องการหรือยัง
__hook().secReport()    // ที่ปลาย marker มีอะไรอยู่ · ใครเป็นเจ้าของ
```

บรรทัดที่ `owner: "nobody"` หรือ `atWantedSize: false` คือจุดที่กฎยังจับไม่ได้ — ส่งมาให้ผมแล้วจะแก้ได้ตรงจุดแทนที่จะเดา
